## Decisions

D8 **Signer sets, parent authority and scoped grants.** Decided (19 November 2026), as an additive change to `originals:1.0`, with no change to the `method` value: a set of one member has exactly the authority of a single author, and an Original with no `authors` member is governed by its single author, so every Original written without the new members verifies unchanged, byte for byte (§5 of the core). For the Originals that use them, these decisions lift D2’s one author per Original and P5.2’s one proof per entry; elsewhere the one-signature rule stands for single-author Originals and for every editor entry.

- **W1, signer sets.** Any Original MAY be governed by a set of member DIDs with a threshold, in an `authors` member, instead of one author (P5.19). Its `author` is an array naming each member who signs, and the extra signatures go in VH-Log’s proof array, one proof per signer in signer order, with no new member (P5.2, P5.22, P14.4, P14.8). Every member signs the genesis entry; later author entries, including changes to the set, anchoring and deactivation, need the threshold of the previous entry’s set, and an added member also signs (P5.20). An Original with one author can become a set Original by an entry that the author and every new member sign, and never goes back (P5.21). Paying for or inscribing an entry gives no authority, and the sat holder still has none (P9.6, P9.12). The derived DID document’s `controller` is the member array (P14.9).
- **W2, authority from a parent Original, pinned.** A child Original names a parent Original at genesis, and each entry pins a version of the parent, which never goes backwards (P5.24). The child keeps its own author or signer set, fixed at genesis; the parent contributes editor grants only, judged at the pinned version (P5.24). Checking them needs the parent’s evidence through the pin (P5.25); a grant the parent later revokes leaves the entries it authorized valid but historically authorized only (P5.26), and an anchored child cannot pin a parent version older than the anchored parent’s head at the child’s inscription (P5.27).
- **W3, scoped grants.** A grant MAY carry a `scope` that narrows what `resource: true` allows. The core checks who may sign; a scope type defines what its scope allows and how to check it, and a verifier that cannot check a scope reports it unchecked, never allowed (P5.28). This profile defines the `paths` and `items` scope types (P5.29, P14.23).
- **Reads.** Read authorization is host-enforced and specified separately. Read grants may later carry `scope`, and are inherited through W2 (P5.29).

Provisional (D4): the member names and shapes (P14.4, P14.5, P14.23), the evidence package layout for parent Originals and scope objects (P14.10), the three new limits (P14.13), and the readings marked PROVISIONAL in P5.23, P5.25, P5.27, P5.28 and P5.29. Open: whether those readings are confirmed, and VH-Log support for a threshold of controllers (release blockers).

D9 **Read authorization.** Decided (owner decisions, 19 November 2026): read authorization is part of this specification, not a companion document. Hosts enforce it; cryptography does not, and encryption remains a later capability (D7, P8.2). The author defines it in the asset state, and a host serving an Original checks it (P8.6, P8.7). Writes stay with editor grants (P5.15–P5.18): every write is an author or an editor entry, and an agent acting for a person has its own did:og, as an editor or a grantee (P8.6). Asset logs still have no witnesses and no service receipts (D3). A read grant covers the whole Original, with room for a scope later (P8.14). A child Original takes its read access from its parent Original (P5.24, P8.10). Whoever holds a copy can read all of it, and host enforcement does not follow copies (P8.12). A host serves bytes by digest only to a requester that may read an Original naming that digest, and answers anyone else as if it did not hold them (P8.11). Anchoring a private Original needs an explicit disclosure, and afterwards read authorization covers only what no inscription carries (P8.13). Proposed in this revision, for owner review: an Original with no `readers` list is public, as hosts treat Originals today, and one with a list, even an empty one, is private (P8.6); read grants sit in the asset state next to editor grants, so each grantee is listed in the log, which a private Original’s hosts serve only to those it permits but which anchoring and shared copies disclose (P8.6, P8.12, P8.13); the author, or each member of a signer set, and the editors may always read (P5.30); a requester proves control of its DID with a signed read request, bound to the host’s origin and a single-use challenge and made with an `authentication` key (P8.9, P14.24); a host decides from the newest verified state it holds, and refuses if any branch it holds refuses (P8.8); a child’s read access follows the newest state of the parent that the host holds, not the pin, so a parent’s revocation stops reads at once although child entries that relied on a revoked inherited grant are only reported as historically authorized (P5.26, P8.10); a requester permitted to read a child may receive the parent’s log through the child’s highest pin (P5.25, P8.10); an unchecked read scope fails closed (P8.14); and at most 128 read grants (P14.13). Open: delegating read access off the log, for example by an editor to its own agents without an author entry; read scopes, which will use the scope types of P5.29; and the read request’s transport.
